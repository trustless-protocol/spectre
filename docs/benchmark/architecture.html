Fast IBC

How it works

A bi-directional IBC v2 bridge. Each direction runs a light client of the other chain; the relayer only forwards messages and is never trusted.

A Cosmos → Ethereum transfer is three steps:

  1. Cosmos emits an IBC send-packet event at block N.
  2. The prover generates a Groth16 proof that validators holding >2/3 of the voting power signed block N.
  3. The proof updates the light client on Ethereum, which then delivers the packet.

Reverse direction (Ethereum → Cosmos) needs no ZK proof: an 08-wasm light client on Cosmos verifies Ethereum's sync-committee signatures and Merkle storage proofs directly, then delivers the packet.
The prover is built on a customized gnark stack, extended for this workload with optimized in-circuit elliptic-curve arithmetic and batched signature verification.
