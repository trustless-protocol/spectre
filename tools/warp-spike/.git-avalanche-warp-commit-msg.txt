feat: cut Avalanche over to the warp light client, settled-height (Helicon) proof pairing throughout

Avalanche now runs on its actual light client: cw-ics08-wasm-avalanche is the
warp client (packages/avalanche-light-client), whose every update verifies a
>=67% stake-weighted aggregate BLS signature from the pinned primary-network
canonical set over the coreth block hash, then a router account proof. The
temporary attestor path for Avalanche is removed (attestor/avalanche daemon,
its script, the avalanche-cchain profile crate, the coreth attested-builder
variant); OP/Base/Arbitrum attested clients are untouched.

The client (9/9 tests, all against live Fuji captures):
- verification: coreth hash recomputation -> exact block-hash warp message ->
  bitset/quorum/BLS (avalanche-warp) -> bounded MPT router proof; private
  AuthenticatedHeader constructor so transitions cannot take unverified input.
- runtime: prepare-then-commit transitions, first-write-wins idempotency,
  parent-hash linkage, misbehaviour freeze on two verified conflicting headers,
  governance rotation (MigrateMsg::ReplaceValidatorSet) strictly monotonic in
  P-Chain snapshot height.
- BLS via a custom querier wire-compatible with the Ethereum client's
  aggregate_verify (same ciphersuite/DST as warp): a hub hosting the Ethereum
  client needs zero chain-side changes. Tests run real BLS through milagro.

Settled-height proof pairing, measured and future-proof for tomorrow's mainnet
Helicon upgrade: under ACP-194 asynchronous execution header(N).stateRoot
commits the state executed through settledHeight(N) (probed empirically on
Fuji: only the proof at the settled height anchors to the header's root), so
every proof paired with a header is now fetched at the header's settled height
— presence-driven from the header itself, no upgrade calendar. Applied to the
warp header builder, and to packet storage proofs in the l2rollup Source
(Avalanche resolves update height -> settled height; a commitment newer than
the settled point re-queues as transient until the frontier advances).

Relayer:
- l2rollup: warp message builder/splitter mirrored byte-for-byte with the wasm
  client and pinned to the same live-captured fixture; NewWarpHeaderBuilder
  drives the signature-aggregator sidecar (re-aggregation is free, nothing
  cached) and refuses an answer over different unsigned bytes.
- config: avalanche-to-cosmos modules carry a `warp` block (aggregator_url,
  network_id, source_chain_id, quorum_num) instead of attestor fields;
  validation enforces exactly one of the two shapes per kind.
- create-clients-cosmos --l2-config gains warp_bootstrap {client_state,
  consensus_state}: states are generated from live chain data by
  `tools/warp-spike -dump-bootstrap` (canonical validator set, bootstrap
  header, settled-height storage root) and submitted verbatim after an
  eth_chainId identity check; the Rust suite pins that exact wire contract by
  deserializing and instantiating a real dumped Fuji bootstrap (73 validators).
